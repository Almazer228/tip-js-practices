## Эксперименты

### Эксперимент 1. Отсутствующий элемент и пустая коллекция

**Прогноз:** `querySelector("#absent")` вернёт `null`, а `querySelectorAll(".absent")` вернёт пустую коллекцию. При обращении к свойству отсутствующего элемента возникнет ошибка.

**Фактический результат:**

```text
Отсутствующий элемент: null
Пустая коллекция: 0
```

При выполнении:

```js
missing.textContent
```

возникла ошибка:

```text
TypeError: Cannot read properties of null
```

**Объяснение:** `querySelector` возвращает `null`, когда элемент не найден.

### Эксперимент 2. `dataset.taskId`

**Прогноз:** значение из `dataset` будет строкой. После `Number()` оно станет числом.

**Фактический результат:**

```text
dataset.taskId → '23'
typeof dataset.taskId → 'string'

Number(dataset.taskId) → 23
typeof Number(dataset.taskId) → 'number'
```

**Объяснение:** значения `data-*` в `dataset` представлены строками, поэтому перед передачей идентификатора в функции ПР2 выполняется преобразование в число.

### Эксперимент 3. Статический `NodeList`

**Прогноз:** сохранённый `NodeList` не будет менять длину после добавления элементов, а новый `querySelectorAll` будет видеть актуальное количество.

**Фактический результат:**

```text
Исходная длина NodeList: 1

После первого добавления:
Старый NodeList: 1
Новый querySelectorAll: 2

После второго:
Старый NodeList: 1
Новый querySelectorAll: 3

После третьего:
Старый NodeList: 1
Новый querySelectorAll: 4
```

**Объяснение:** `querySelectorAll` возвращает статический `NodeList`. Для получения нового состояния выполняется новый запрос.

### Эксперимент 4. Строка с HTML-разметкой

**Прогноз:** строка с `<strong>` будет выведена как текст и не создаст HTML-элемент.

**Фактический результат:** после нажатия на «Изменить заголовок» на странице отображается строка:

```text
<strong>Это текст, а не HTML</strong>
```

Дополнительная проверка:

```js
document.querySelector("#lab-title").children.length
```

результат:

```text
0
```

**Объяснение:** для вывода используется `textContent`, поэтому строка не интерпретируется как HTML.

### Эксперимент 5. Распространение события

**Фактический результат при нажатии на вложенный `span`:**

```text
1. phase=1; target=lab-label; currentTarget=lab-card
2. phase=3; target=lab-label; currentTarget=lab-button
3. phase=3; target=lab-label; currentTarget=lab-card
```

**Объяснение:** `event.target` указывает на элемент, по которому произошёл исходный клик, то есть `lab-label`. `event.currentTarget` показывает элемент, на котором в данный момент выполняется обработчик. Событие сначала проходит фазу захвата, затем всплывает обратно по родительским элементам.

## Организация кода

В проекте используются четыре основных модуля.

`task-service.js` — прикладные функции из ПР2: создание, поиск, изменение статуса, переименование, удаление и расчёт статистики.

`task-selectors.js` — функция `getVisibleTasks`, которая формирует видимый массив для фильтров `all`, `pending` и `completed`.

`task-view.js` — создание DOM-карточек, вывод списка, сводки и сообщений о пустом состоянии.

`main.js` — хранение текущего массива и фильтра, обработка событий, вызов функций ПР2 и повторная отрисовка.

Полный текущий массив хранится в `currentTasks`, а выбранный фильтр — в `currentFilter`. Видимые задачи вычисляются отдельно и не заменяют полный массив.

## Отладка и клавиатура

Во время исследования DOM через Console проверен идентификатор:

```text
dataset.taskId = "23"
тип = string
Number(dataset.taskId) = 23
тип после Number = number
```

```text

currentTarget = lab-card
currentTarget = lab-button
currentTarget = lab-card
```

Проверено, что событие доходит до обработчика кнопки через всплытие.

Также проверена работа интерфейса с клавиатуры через `Tab` и `Enter`. Фокус перемещается между интерактивными элементами. После изменения задачи фокус сохраняется на соответствующем действии.

Для некорректных идентификаторов предусмотрены проверки `777` и `4abc`. Такие значения не должны изменять массив задач.
