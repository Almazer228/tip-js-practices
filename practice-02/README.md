## 4. Модель данных и функции

Одна задача хранится как объект:

```js
{
  id: 20,
  title: "Подготовить демонстрацию",
  completed: false,
  priority: "medium"
}
```

`id` — положительное безопасное целое число.

`title` — строка от 1 до 100 символов. Пробелы в начале и конце убираются.

`completed` — `true` или `false`.

`priority` — `low`, `medium` или `high`. Если приоритет не передан, используется `medium`.

В `task-service.js` находятся все функции для работы с задачами:

* `createTask` — создание задачи;
* `findTaskById` — поиск по `id`;
* `getPendingTasks` — получение невыполненных задач;
* `getTaskTitles` — получение названий;
* `getTaskStats` — расчёт статистики;
* `addTask` — добавление;
* `setTaskCompleted` — изменение статуса;
* `renameTask` — изменение названия;
* `removeTask` — удаление.

При ошибке функции изменения данных возвращают объект с `ok: false`, а не останавливают программу.

**Почему `id` не равен индексу:** индекс показывает место элемента в массиве и начинается с 0. `id` нужен для идентификации самой задачи. Например, задача с `id = 4` в исходном массиве находится по индексу `1`.

**Почему `getTaskStats` возвращает число, а не строку с процентом:** `progress` сначала считается как число. Уже при выводе оно форматируется через `toFixed(1)`.

**Какие объекты копируются при изменении задачи:** создаётся новый массив и новый объект той задачи, которую меняем. Остальные объекты не приходится копировать.
