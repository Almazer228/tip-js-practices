## 4. Задание 1: Запуск кода в Node.js и браузере
Один и тот же файл `hello.js` выдал разный результат в самом конце:
* **В терминале через Node.js:** `Тип document: undefined`
* **В консоли браузера:** `Тип document: object`

**Почему так:** Браузер создан для работы с веб-страницами, поэтому у него внутри есть встроенный объект `document` (DOM) для управления элементами на экране. А Node.js — это среда для запуска кода прямо на компьютере или сервере. Никаких страниц там нет, поэтому и объекта `document` не существует (он равен `undefined`).

## 8. Доп. задание: Вариант А (Ввод через строки)
Написал скрипт `progress-input.js`. Он принимает данные в виде строк, чистит скрытые пробелы с помощью `trim()`, проверяет на пустые поля, отлавливает дробные числа, `NaN`, `Infinity`, `null` и `undefined`, защищая код от вылета.

**Почему нельзя просто бахнуть `Number()` и проверить, что число больше нуля?**
1. `Number("")` и строка с пробелами `Number("   ")` превращаются в обычный ноль `0`. Код посчитает пустой ввод нормальным числом, хотя пользователь ничего не ввел.
2. Текст вроде `Number("abc")` вернет `NaN`. Если проверить `NaN >= 0`, вернется ложь (`false`), но этот `NaN` пойдет дальше по коду и сломает всю последующую математику (везде полезут ошибки `NaN`).
3. Если случайно прилетит другой тип данных (например, `null`), то `Number(null)` выдаст `0`, замаскировав ошибку под реальный ноль задач.
