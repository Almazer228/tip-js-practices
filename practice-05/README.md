## Эксперимент с очередями выполнения

До запуска был сделан прогноз порядка выполнения операций.

| Этап | Порядок меток | Объяснение |
|---|---|---|
| Прогноз до запуска | A → B → C → D → E → F | Сначала выполняется синхронный код, затем микрозадачи Promise и продолжение async-функции, после чего выполняется таймер. |
| Фактический результат | A → B → C → D → E → F | Фактический порядок совпал с прогнозом. |
| После добавления собственного Promise | A → B → C → D → E → G → F | Новый обработчик Promise выполняется до задачи таймера. |

Синхронный код выполняется первым. Продолжения Promise и `await` относятся к микрозадачам. Таймер с задержкой 0 не выполняется немедленно, а ожидает завершения текущего кода и микрозадач.

## Организация кода

| Файл | Ответственность |
|---|---|
| `api/server.mjs` | Готовый учебный HTTP API. Обрабатывает запросы и возвращает задачи и категории. |
| `src/api-client.js` | Общий HTTP-клиент. Формирует URL, выполняет запросы, разбирает JSON и обрабатывает ошибки. |
| `src/task-api.js` | Предметный модуль для работы с задачами и категориями. Проверяет структуру полученных данных. |
| `src/variant.js` | Хранит номер индивидуального варианта и фильтры. |
| `src/main.js` | Выполняет контрольный сценарий и выводит результат в терминал. |

Функция `fetchFn` передаётся в `createApiClient` аргументом, чтобы можно было проверять клиент без реальной сети.

HTTP-ошибки отделяются от сетевых, поскольку получение ответа с кодом 404 или 503 не означает отсутствие соединения.

После разбора JSON данные дополнительно проверяются по контракту, чтобы приложение не использовало объекты неправильной структуры.

## Реализация общего клиента

| Требование | Как реализовано |
|---|---|
| Формирование URL | Функция `buildUrl()` соединяет адрес сервера и путь. |
| Кодирование query-параметров | Используется `URLSearchParams`. |
| Сохранение false и 0 | Значения не теряются при формировании URL. |
| Заголовок Accept | Передаётся `application/json`. |
| Проверка response.ok | Проверяется успешность HTTP-ответа. |
| Проверка Content-Type | Проверяется формат JSON. |
| Разбор JSON | Используется `response.json()`. |
| Ответ 204 | Возвращается `null`. |
| Ограничение времени | Используется `AbortSignal.timeout()`. |
| Внешняя отмена | Используется `AbortController` и `AbortSignal.any()`. |

## Классификация ошибок

В клиенте реализован класс `ApiError` с единым набором свойств.

| Сценарий | Тип ошибки | Обработка |
|---|---|---|
| Задача `999` | `http` | Сохраняются статус 404 и код `TASK_NOT_FOUND`. |
| Неверный фильтр | `http` | Сохраняются статус 400 и код `INVALID_QUERY`. |
| Ошибка сервера | `http` | Сохраняется статус 503 и код `SERVICE_UNAVAILABLE`. |
| Повреждённый JSON | `invalid-response` | Ответ отклоняется как некорректный. |
| Текст вместо JSON | `invalid-response` | Проверка Content-Type выявляет неправильный формат. |
| Нет соединения с сервером | `network` | Сохраняется причина сетевой ошибки. |
| Превышено время ожидания | `timeout` | Запрос отменяется по тайм-ауту. |
| Внешняя отмена | `aborted` | Запрос отменяется через AbortController. |

Для обработки ошибок используются свойства `kind`, `status`, `code`, `details`, `url` и `cause`.

## Доменный модуль задач

В `task-api.js` реализованы следующие методы:

| Вызов | Результат |
|---|---|
| `getTasks()` | Получение полного списка из 12 задач. |
| `getTasks({ completed: false, priority: "high" })` | Получены задачи с ID 4, 13, 34. |
| `getTaskById(25)` | Получение задачи по ID. |
| `getCategories()` | Получение трёх категорий: Учёба, Проект, Организация. |
| `loadInitialData(...)` | Параллельная загрузка задач и категорий. |

Для задач проверяются ID, название, статус выполнения, приоритет и ID категории.

Для категорий проверяются ID и название.

Также проверяются уникальность ID и соответствие `meta.total` количеству записей.

## Последовательная и параллельная загрузка

Для сравнения использовались два одинаковых запроса с задержкой 150 мс. Каждый вариант был запущен три раза.

| Сценарий | Запуск 1, мс | Запуск 2, мс | Запуск 3, мс |
|---|---:|---:|---:|
| Последовательная загрузка | 323,0 | 303,8 | 305,4 |
| Параллельная загрузка | 156,6 | 153,7 | 154,1 |

При последовательном выполнении второй запрос начинается после завершения первого.

При использовании `Promise.all` оба запроса выполняются одновременно. Поэтому общее время ожидания получается меньше.
